### 2026/07/30 v2.10.2
### パーミッション
- `config.php`のパーミッションが`0600`に自動的に変わるようにしました。  
`.htaccess`で外部に表示しないようにしていました。  
また、直接アクセスしても何も表示されない筈です。  
しかしながら共用サーバの別ユーザによる操作の可能性はありました。    
[第三者によるユーザーサイトの改ざん被害に関するご報告 - ロリポップ！レンタルサーバー](https://lolipop.jp/info/news/4149/)  
このケースでは`wp-config.php`のパーミッションが0644だった事が悪用されました。  
そのため、`config.php`のパーミッションが自動的に0600になるようにしました。    
普通に考えると共用サーバの別ユーザによるファイル操作ができる事自体が問題ですが、機密情報の入ったファイルには`0644`を使わないようにするという防御はエンドユーザーにもできる事なので今回対策を行いました。    

- `log/`ディレクトリのパーミッションを`0700`に   
ログファイルそのものは`0600`になっているものの、なにかの操作で外部から覗く事ができるパーミッションに変わる事があるかもしれません。  
しかし、ログファイルが格納されているディレクトリのパーミッションが`0700`であれば外部からの操作を防ぐ事ができます。    
### GETパラメータで開いて欲しくないモード
- POSTリクエストしか受け付けていない処理のモードがGETパラメータで表示される問題を修正しました。  
表示されるといってもエラーメッセージか、何も表示されていない画面でしたが、GETパラメータを様々に試行して攻撃するBOTはそういった箇所に隙があるはずだと考えて攻撃を開始します。  
そのため、POSTリクエストしか受け付けていない処理をGETパラメータで開いた時は403エラーを返すようにしました。

### 2026/07/25 v2.8.6
### パスワードなどの機密情報をGETパラメータで使用していた箇所を削除
- 古くからの慣習で、GETパラメータで画像の差換えのためのパスワードを送信する事がありました。      
しかしそれは、そのURLがわかれば、パスワードもわかるという事を意味しています。    
そのため、POSTによるより安全な処理に移行する方法を模索し、安全なPOSTによる処理に移行していました。  
その時に、古い方式が必要な場合があるかもしれないと考えて、GETパラメータでパスワードを受け取る処理も残してしまいました。  
このセキュリティの穴を完全に除去するため、GETパラメータを使った画像の差換えのための機密情報の受け渡し処理を完全に削除しました。  
これまでも生のパスワードをGETにセットするべきではないと考えてOpenSSLで暗号化するなどの対策は行っていました。     
しかし、暗号化されたパスワードが漏洩すれば、その暗号化されたパスワードを復号化している処理では、暗号化されたパスワードそのものが開くための鍵になってしまいます。    
またオープンソースであるため、復号鍵が漏れていれば暗号化されたパスワードを復号化できてしまいます。    
そのため、GETパラメータを使用したパスワードの受け渡し処理を完全に削除しました。
### 年齢確認ボタン押下後にスレッドの途中にある画像までスクロールしない問題を修正
- `?resno=367&resid=1784186121844160`のように、`resid`が指定されている時は、ページ内にある画像の位置までスクロールする仕様です。   
しかしながら、年齢確認ボタン押下後にリロードしていたため、ブラウザのリロード前の位置を復元する機能が働いてしまい、ページ内画像までスクロールしない状態になっていました。  
現在のURLをそのまま再度表示する処理に変更しこの問題を修正しました。

### 2026/06/14 v2.0.5
### 管理者ログイン･続きを描く･Misskeyにノートなどパスワード入力をともなう箇所の表示をGETからPOSTへ
#### 攻撃されやすいGETパラメータを使用した表示項目をPOSTへ
- 管理者ログイン･続きを描く･Misskeyにノートの各画面はこれまでURLを直打ちすることで画面を表示する事ができていました。  
そのため、セキュリティの脆弱性を狙うボットの攻撃対象となる事がありました。  
GETパラメータを様々に変更してなんらかのサーバの機密情報を取得するこころみが行われる事が多々ありました。   
情報が漏洩しなかったとしても、この攻撃により、サーバが不安定になる事もありました。  
そのため、管理者ログイン、続きを描く、Misskeyにノートなどのパスワードの入力を伴う箇所の表示を、URLで指定するGETではなく、POSTに切り替えます。  
#### テンプレート互換性問題
-  しかしながら、このGETのURL指定方式を廃止すると、古いバージョン1.xのテンプレートでは、管理者ログインも続きを描く事もできなくなってしまいます。    
テンプレートのすべてが変わった訳ではなく、ごく一部ではありますが、テンプレートの改造をして見た目のカスタマイズをしている方にとっては、大きな変更になってしまうかもしれません。  
そのため、バージョン1.xの従来のテンプレートでも使用できるようにするための互換設定項目をconfig.phpに追加しました。  

```
//セキュリティを犠牲にして古いバージョン1用のテンプレートを使用する
// する: true しない: false

// この設定項目は互換性のためだけに存在しています。
// この設定項目が最初から存在している場合はすでに対応テンプレートになっているため、設定を変更する必要はありません。

 $enable_v1_legacy_template_unsafe_get_login = true;
//$enable_v1_legacy_template_unsafe_get_login = false;

```
` $enable_v1_legacy_template_unsafe_get_login = true;`に設定することで、従来の`?mode=adminin`で管理者ログインができるようになり、続きを描くリンクも以前と同じものが使えるようになります。  
しかし、サーバへの攻撃が発生するかもしれず、パスワードを突破される可能性も高くなるGETパラメータによるこれらの画面の表示は可能であれば使用しないほうが良いと思われます。    

- テンプレートのフォルダを全部更新する分には、転送するだけで終わる作業なのですが、Javascriptのcommon.jsの更新も必要で、index.cssにも以下が追加されています。

```
/* リンクでPOST */
.ref-target-do-submission{
    cursor: pointer;
    /* リンクのaタグと同じ見た目になるように装飾 */
    text-decoration: underline;
    color: var(--a-color);
}
.ref-target-do-submission:hover{
    /* リンクのaタグと同じ見た目になるように装飾 */
    text-decoration: none;
    color: var(--a-hover-color);
}
```
新しいテンプレートでは、このような指定を追加する必要があり、これらのCSSの指定が無い場合は、リンクの下線などが表示されず、マウスオーバしても指の形に変わりません。    
実際はspanタグで記述されている箇所をあたかもリンクのような見た目にするためのCSSです。

### 2026/01/04 v1.169.1
### 位置情報が入った写真が公開されるリスクを軽減
#### 位置情報(Exifなどに含まれる)をより徹底的に削除するようになりました
- スマホで撮影した写真には位置情報(GPSデータ)が入っている事があります。   
位置情報が付くスマホの｢写真｣には、自宅で撮影した｢イラスト｣の写真も含まれます。  
これまでは、画像の形式がjpegで、PHPが位置情報を検出した場合にのみGDで新しく画像を作り直して情報を削除していました。  
また、初期設定値であれば幸いな事にスマホの写真のサイズは1024pxを超えている事がほとんどのため、画像のリサイズ処理が行われた時に位置情報が消えていました。  
しかしながら、WebP形式やPNG形式画像にもExifなどに含まれる位置情報(GPSデータ)が入ります。  
これをxnViewなどの画像ビューワーであらかじめリサイズされる制限値より小さなサイズにリサイズすると、掲示板のPHPのリサイズ処理は入らないため、そのままアップロードされていました。  
PNG形式･WebP形式の画像ファイルの位置情報の有無はPHPでは検出する事ができないため、位置情報のチェック処理が機能していませんでした。  
そのため位置情報の検出の有無に関わらず、GDで画像を作り直して上書きします。  
これによりすべてのアップロード画像のExifそのほかの位置情報を消去します。  
- ただしGDが機能しない場合もありえるため、あらかじめ位置情報が公開される事が無いようにカメラの設定や公開する画像の情報の確認をお願いします。  
- 通常のレンタルサーバの環境であれば、GDで作成された画像で毎回上書きされ、位置情報は残らななくなるものと思われますが、バグが100%無い事を保証する事は困難なため、位置情報が100%消える事も保証できません。  
十分にご注意ください。
